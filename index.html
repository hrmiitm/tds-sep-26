Windows paths: separate drive roots

Home matters. Keep your Linux projects under ~. Linux supports multiple users; ownership and permissions control their access.

/ is the filesystem root. /root is the administrator’s home. They are different locations.

02 / Meet your system15–18 min

Enable WSL. Open Ubuntu. Start there.

Official WSL setup ↗

  1. Use Windows 11, or supported Windows 10 (2004 / build 19041 or later).
  2. Open PowerShell as Administrator.
wsl --install -d Ubuntu

This enables the required WSL features and installs Ubuntu. Restart if prompted, open Ubuntu, then create a Linux username and password.

Type sudo apt … inside Ubuntu. Type wsl … in PowerShell.

Manage WSL ↗

PowerShell commandAction
wsl -l -vInstalled distros + WSL version
wsl --list --onlineAvailable distro names
wsl --install -d UbuntuInstall a named distro
wsl -d UbuntuOpen that distro
wsl --updateUpdate WSL itself
wsl --shutdownStop running WSL environments
Remove a distro · deletes its Linux files

wsl --unregister Ubuntu permanently deletes Ubuntu’s WSL filesystem and settings. Back up its files first. This is a reference command, not a setup step.

Already on Ubuntu or Fedora? Use your native terminal. A Linux password shows no characters while you type.

Command + options + arguments.

01 · Tokenize Split into words and operators. Quotes keep text together.

02 · Expand$HOME → /home/student. The quoted path stays one argument.

03 · Does the command word contain /?

YES → use that path

/usr/bin/ls → absolute: start at /.
./hello.sh, ../hello.sh, bin/tool → relative: start here.

Run the named file. Skip PATH lookup.
NO → look up the name

ls, git, myscript, .hidden

Function→Builtin→Cache / PATH
Search PATH left to right; run the match.
04 · Run

For our example, Bash starts ls with -lh and the expanded path. ls interprets its options and lists that directory.

The rule is a slash anywhere, not “starts with a dot”. Operators such as | and > are shell syntax, not tool arguments.

Paths: absolute, relative and home.

Two rules, after expansion

Starts with /?

Absolute. Begin at the filesystem root.

Doesn’t start with /?

Relative. Begin at the current working directory.

~ and $HOME are shortcuts that expand to your home’s absolute path. A quoted "~" does not expand.

03 / Read the command29–31 min

./myscript or myscript?

Bash treats the first word as the command. A slash changes how it finds that command.

Contains / → explicit path
./myscript
This folder → myscriptRun this file. Skip PATH lookup.

The file must exist, be executable, and have an available interpreter.

No / → command-name lookup
myscript
Function → builtin → PATHRun the match, or report “command not found”.

The current folder is usually absent from PATH. Even .myscript is a name; use ./.myscript to run that local file.

bash ./myscript resolves Bash as the command; ./myscript is its file argument. Bash reads the script, so the script itself needn’t have execute permission.
04 / Connect the pieces31–32 min

Choose where the streams go.

stdin · 0keyboard or file input
→
Programdoes the work
→
stdout · 1normal output
stderr · 2errors / diagnostics
Bash syntaxWhat changes
cmd > out.txtWrite stdout into a file; replace existing content.
cmd >> out.txtAppend stdout to the file.
cmd < input.txtRead stdin from a file instead of the keyboard.
cmd 2> errors.txtSave stderr separately. 2>> appends errors.
cmd > all.txt 2>&1Send stdout to the file, then send stderr to the same place.
Bash connects the streams. The tool performs the task; the shell decides where its input and output go.

Bash redirections

04 / Connect the pieces32–34 min

A pipe sends data to the next tool.

printfcreate three lines
→
grep applekeep matching lines
→
wc -lcount them → 2
printf 'apple\nbanana\napple\n' | grep "apple" | wc -l
Useful Bash formsMeaning
cmd1 | cmd2stdout of the first → stdin of the second.
cmd1 |& cmd2Pipe both stdout and stderr.
cmd &> all.txtSave both streams; &>> appends them.
cmd > /dev/nullDiscard stdout. Errors still appear.
cmd << EOF / <<< "text"Input from a here-document / here-string.

Order matters: > all.txt 2>&1 differs from 2>&1 > all.txt. A pipe carries output; && checks success (next slide).

Bash pipelines

04 / Connect the pieces34–36 min

Several commands. One small script.

Choose when the next command runs

SyntaxBehaviour
first ; secondRun second after first finishes
first && secondRun second only if first succeeds
first || secondRun second only if first fails
first &Start first in the background
mkdir -p ~/linux-day1 && cd ~/linux-day1
# This is a comment: Bash ignores it.
ls -lh \
  "$HOME/linux-day1"

A newline separates commands. A final \ continues the same command on the next line; put no spaces after it.

Save commands in hello.sh

cat > hello.sh <<'EOF'
#!/usr/bin/env bash
# A tiny Bash script
printf 'Hello Linux\n'
pwd
EOF

bash hello.sh

cat writes the here-document into the file. The quoted 'EOF' preserves the script text without expanding variables now.

#!/usr/bin/env bash names the interpreter for direct execution. We add execute permission next.

04 / Connect the pieces39–42 min

Permissions: add 4, 2 and 1.

4r · read
2w · write
1x · execute
7rwxOwner · 4 + 2 + 1
5r-xGroup · 4 + 1
5r-xOthers · 4 + 1

chmod 755 hello.sh sets the digits above. 6 = 4 + 2 means read/write; 0 means none.

Make your script executable

chmod +x hello.sh
./hello.sh

+x adds execution; read/write bits stay. With no class given, umask limits which classes receive it.

Use chmod u+x hello.sh to add execution for the owner explicitly.

chmod 700 hello.shOnly the owner gets ordinary access
chmod 644 notes.txtOwner reads/writes; others read
The same step often enables a downloaded command-line script: inspect it, add the needed execute bit, then run its explicit path.

05 / Set up your tools42–45 min

Add a tool to PATH. Keep it there.

Add its containing directory. Preserve the folders already in PATH.

Temporary · this shell + its children
export PATH="$HOME/.local/bin:$PATH"
command -v uv
~/.local/binyour added directory
→
existing PATHkeep the old search list

: separates directories. Prepending means this folder is searched first. Adjust it to where your tool is actually installed.

Persistent · future interactive Bash sessions

Open the startup file:

nano ~/.bashrc

Add this line once inside the file:

export PATH="$HOME/.local/bin:$PATH"

Save: Ctrl+O → Enter → Ctrl+X. Apply it now:

source ~/.bashrc
command -v uv

Interactive, non-login Bash reads ~/.bashrc. Login shells may load it through another startup file. Zsh uses different settings.

05 / Set up your tools49–51 min

Give Git an identity. Point tools to Java.

Git · first-time setup ↗

git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
git config --global init.defaultBranch main

git config --global --list

Replace the example identity. This sets commit metadata and the default branch for new repositories.

Git is local version control. GitHub hosts repositories. These commands do not sign you into GitHub.

JAVA_HOME · the JDK folder

First check java -version and javac -version. Set JAVA_HOME if your build tool needs it.

Ubuntu default JDK · add once
echo 'export JAVA_HOME="/usr/lib/jvm/default-java"' >> ~/.bashrc
source ~/.bashrc
Fedora / another selected JDK · derive its root
export JAVA_HOME="$(dirname "$(dirname "$(readlink -f "$(command -v javac)")")")"
printf '%s\n' "$JAVA_HOME"

For future Bash sessions, put that verified export line in ~/.bashrc, then source ~/.bashrc. JAVA_HOME names the directory above bin.
